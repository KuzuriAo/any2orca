Output-affecting: **Files are converted for the nozzle size your U1 has, 0.4 mm unless you say otherwise, instead of the size the creator used.** A MakerWorld project sliced for a 0.6 mm nozzle used to become a U1 0.6 conversion, which the U1's firmware refuses at print start when 0.4 mm nozzles are installed. Now the profile, its layer heights and the filament values are the U1's for your size, the creator's size is noted when it differs (with a What changed item under Your choices), and a project that mixes nozzle sizes (Bambu Studio's multi-diameter mode, as on the H3C) is converted for your size with a note naming the filaments that were on other sizes. A project that names no nozzle size is converted for your size too, matched by its layer height, where it used to get the catalog's default profile whatever its layer height. The size is one for all four toolheads, as Snapmaker Orca allows; a release that allows a different size per toolhead will say so in its profile catalog (`catalog.mixedNozzleSizes`), which is where per-toolhead sizes would start. Library: the `nozzle` option on `convert()` and `matchProfile()` (`"0.2"` to `"0.8"`, or `"match"` for the creator's size, the old behavior); `NOZZLE_CHOICES` and `DEFAULT_NOZZLE`; `report.nozzle` and `ProfileChoice.nozzle` say what was used; `inspection.nozzleDiameters` lists every size a project uses; the version note records `options.nozzle`. CLI: `--nozzle <size|match>` on `convert`, and `any2orca nozzle <size>` saves your size in the config file for every conversion. Refused together with a `--profile` or preset of another size.

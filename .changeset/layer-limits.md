"any2orca": minor
---

Features: **A note when the creator's layers are thinner or thicker than the nozzle supports, and an option to convert with one layer height.** Snapmaker Orca slices a layer height outside the nozzle's range as it is, with no warning, and the conversion said nothing either. A project's variable layer heights, the layer heights set for ranges of an object's height and the layer heights set on objects stay as the creator set them whatever the nozzle size, so a 0.1 mm layer on the 0.6 mm nozzle (which supports 0.12 to 0.42 mm) printed that way unnoticed, as did 0.2 mm layers on the 0.2 mm nozzle (which supports 0.04 to 0.14 mm). Now a note under the new topic `layers` (in `NOTE_TOPICS`, after `profile`) says the project has layers as thin (or as thick) as a given height, what the nozzle supports, and that they stay as set. Where the thin or thick layers come from an object's variable layer heights, it names the objects (the file stores the heights a layer height tool made, not the tool's settings) and says that a layer height set in Snapmaker Orca doesn't clear them. In a check of 447 real projects converted for each nozzle size, the note applies to 4 on the 0.4 mm nozzle (0.9%), 17 on 0.6 mm (3.9%), 23 on 0.8 mm (5.2%) and 40 on 0.2 mm (9.1%). The new `layerHeight` option (`--layer-height <mm>` on the command line) converts the project with one layer height, one of the heights the U1's profiles for the nozzle have, which replaces the creator's variable layer heights and the layer heights set for ranges of an object's height or on objects; a `layers` note says which were replaced, and the file's version note records the height. The layer notes are in `report.notes` only, not in the older `report.warnings`, so an app that shows the warnings adds the `layers` notes from `report.notes`. A height no profile of the nozzle has is refused, naming the ones that exist; it can't be combined with `profileId` or a preset. Without the option the creator's variable layer heights, ranges' layer heights and objects' layer heights are kept, as before. Checked in Snapmaker Orca 2.4.1: a project with variable layer heights on four objects, converted with `layerHeight: 0.18`, slices at 722 layers that are all exactly 0.18 mm. Library: `layerHeight` in the conversion options, and on each plate of `inspection.plateFilaments` and `report.plateFilaments` `layerHeights`, the thinnest and thickest layer it prints in mm (the first layer aside), with `variable` naming by id the objects whose layers vary. CLI: `convert --layer-height`, `inspect` prints a `Layers` line for each plate and `--json` carries `layerHeights`, and a problem report's plate line gives the layers. The new layer-height example shows a project's layers against the nozzle and converts it with one layer height.

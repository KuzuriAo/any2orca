"any2orca": minor

Features: **A note when the creator's layers are thinner or thicker than the nozzle takes.** Snapmaker Orca slices a layer height outside the nozzle's range as it is, with no warning, and the conversion said nothing either. A project's variable layer heights, a height range's own layer height and an object's own layer height are kept as the creator set them for any nozzle size, so a 0.1 mm layer on the 0.6 mm nozzle (which takes 0.12 to 0.42 mm) printed that way unnoticed, as did 0.2 mm layers on the 0.2 mm nozzle (which takes 0.04 to 0.14 mm). Now a `nozzle` note says the project has layers as thin (or as thick) as a given height, that they stay as set, and which heights to set instead in Snapmaker Orca. In a check of 447 real projects converted for each nozzle size, the note applies to 6 on the 0.4 mm nozzle (1.4%), 25 on 0.6 mm (5.7%), 31 on 0.8 mm (7%) and 43 on 0.2 mm (9.8%). Converted files don't change. Library: each plate of `inspection.plateFilaments` and `report.plateFilaments` has `layerHeights`, the thinnest and thickest layer it prints in mm, the first layer aside: from the layers the slicer builds where they can be worked out (variable layer heights included), otherwise from the layer heights the file sets. CLI: `inspect` prints a `Layers` line for each plate, `--json` carries `layerHeights`, and a problem report's plate line gives the layers. The plate-filaments example prints them.
